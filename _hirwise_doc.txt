A Responsible Multi-Agent AI System for Explainable Candidate Shortlisting
One problem you solve
Recruiters often receive many CVs for one vacancy. Manually reading all CVs takes time, and early screening can become inconsistent when different recruiters prioritize different information.
Your system solves only this problem:
Help HR officers conduct faster, consistent, transparent, and privacy-aware first-stage candidate shortlisting from CVs.

Agent 1: Candidate Intelligence Agent
Purpose
Convert an unstructured CV into a clean, anonymous, structured profile. This agent prevents downstream agents from seeing unnecessary personal identifiers.
Inputs
Candidate CV in PDF or DOCX.
Candidate ID generated by the mini ATS, for example CAND-024.
Optional configured list of sensitive fields to redact.
Tasks
Validate file type, size, and malware-safe upload rules.
Extract text from the CV.
Use NLP and/or an LLM to identify:
Technical skills.
Soft skills.
Job titles.
Employers.
Education.
Certifications.
Projects.
Work experience dates.
Calculate total relevant experience where possible.
Detect and remove personally identifiable information.
Store the original CV securely; send only an anonymous profile to Agent 2.
Provide an extraction-confidence score and flag missing or unreadable documents.
Sensitive information to exclude
The matching score must not use:
Full name.
Photograph.
Gender.
Date of birth or age.
National ID/passport number.
Email address and phone number.
Home address.
Religion.
Ethnicity.
Marital status.
Disability status.
Nationality, unless there is a clearly documented legal work-eligibility requirement.
University name, unless your scoring rubric explicitly and legitimately requires it.
Technologies
PyMuPDF, pdfplumber, or Apache Tika for PDF text extraction.
python-docx for DOCX files.
spaCy for NER.
Regex patterns for email, telephone, ID, and date detection.
An LLM for structured extraction into a validated JSON schema.
Pydantic validation to ensure the output is clean and predictable.
Agent 2: Job Matching & Retrieval Agent
Purpose
Determine how well an anonymized candidate profile matches a specific job using approved, predefined, job-related criteria. It should retrieve the requirements and scoring rules from a knowledge base rather than inventing them.
Inputs
Job ID and job description.
Anonymous candidate profile from Agent 1.
Role competency knowledge base.
Scoring rubric configured by HR.
Tasks
Extract job requirements from the vacancy:
Mandatory skills.
Preferred skills.
Minimum relevant experience.
Essential qualifications.
Key responsibilities.
Retrieve the most relevant job-role rubric and skill definitions from the vector database.
Normalize skill names:
“MS Excel” → “Excel.”
“Structured Query Language” → “SQL.”
“PowerBI” → “Power BI.”
Match candidate evidence to each requirement.
Calculate a transparent, fixed score.
Return both the score and the evidence used for every score component.
Flag uncertain matches instead of assuming they are true.
Information retrieval knowledge base
Prepare 10–20 small documents or records, such as:
Data Analyst competency framework.
Software Engineer competency framework.
HR Assistant competency framework.
Approved job descriptions.
Skill taxonomy and synonyms.
Recruitment scoring rubric.
Definition of mandatory versus preferred criteria.
For example, if the job description says “strong data visualization capability,” Agent 2 retrieves related terms such as Power BI, Tableau, Looker Studio, and visualization dashboards from the skill taxonomy.
Transparent scoring rule
For a Junior Data Analyst role:

Match Score=0.45(mandatory skills)+0.25(experience)+0.15(education)+0.15(preferred skills)
Do not use an LLM alone to produce the final numeric score. Let the LLM help extract and explain information, but make the score based on fixed, auditable rules
Agent 3: Responsible Decision Agent
Purpose
Ensure that the system’s output is safe, explainable, privacy-aware, and explicitly subject to human review. This agent never makes a final hiring decision.
Inputs
Anonymous candidate profile from Agent 1.
Scoring and evidence from Agent 2.
Sensitive-data redaction results.
Matching and extraction confidence.
HR-configured thresholds.
Tasks
Verify that no prohibited or sensitive fields were used in scoring.
Check whether all required scoring evidence exists.
Flag low-quality CV parsing or uncertain requirement matches.
Apply human-review rules:
Low extraction confidence.
Low matching confidence.
Missing mandatory evidence.
Unusual score pattern.
Tie or borderline score.
Generate a plain-language explanation.
Assign a recommendation, not a hiring decision.
Store an audit trail.
Support a fairness test mode using paired CVs with equivalent qualifications but different identity details.
Recommendation categories
Use cautious labels:

Avoid using “Rejected” as an automated system output.
Responsible recruitment guidance stresses that applicants should be informed about how AI uses their information, and AI outputs should receive meaningful human review to catch errors and bias
Communication design
Use REST APIs over HTTP with JSON. It is easy to implement, demonstrate, test with Postman, and explain in the viva.

One-minute version(leader)
Our domain is Human Resource Management, and our focus is recruitment and candidate shortlisting. The problem is that HR recruiters receive many CVs and manually screening them takes time and can be inconsistent. Our planned solution is HireWise, a responsible multi-agent AI system for explainable candidate shortlisting.
The system will be used through a simplified ATS dashboard, where a recruiter creates a job vacancy and uploads CVs. Our first agent extracts skills, education, and work experience from a CV while removing personal data. The second agent compares the anonymous candidate profile with job requirements and retrieves relevant skill criteria from a knowledge base. The third agent checks fairness, privacy, and confidence, then generates an explanation and recommendation.
The system will not automatically hire or reject candidates. It will only support the recruiter with transparent recommendations, and the final decision will always be made by a human.
HireWise is a web-based, multi-agent AI decision-support system for initial candidate shortlisting. It accepts job descriptions and CVs, anonymizes candidate data, retrieves job-related criteria, produces evidence-based matching results, checks Responsible AI conditions, and provides an explainable recommendation for human HR review. It is not a full Applicant Tracking System and does not make final hiring decisions.





HireWise Recruiter Dashboard
you should create a small frontend where an HR recruiter uploads CVs and enters a job description. But it should be a simple HireWise Recruiter Dashboard, not a large public job portal or full ATS.
The frontend is mainly needed to demonstrate a realistic end-to-end flow: recruiter provides the job and CVs → agents process them → recruiter sees an explainable recommendation → recruiter makes the final decision.
What frontend you need
Build only a small internal HR interface. You do not need candidates to create accounts or apply through the system.
Minimum screens

This is enough to make a strong demo. Do not build public registration, LinkedIn job posting, interview scheduling, candidate emails, payroll, or onboarding.

Database design
You need two different storage systems, because your assignment includes both normal application data and an information-retrieval module.
1. Relational database: PostgreSQL
Use PostgreSQL to store structured application data:
HR users and roles.
Job vacancies.
Candidate records.
CV metadata.
Extracted candidate profiles.
AI scores and explanations.
Human recruiter decisions.
Security/audit logs.
PostgreSQL is suitable because your system has related entities: a job has many candidates; a candidate can have results for a particular job; and every decision should be traceable. For FastAPI, SQLModel is a simple option because it combines SQLAlchemy database support with Pydantic-style data validation. 
2. Vector database: ChromaDB
Use ChromaDB only for your Information Retrieval requirement.
Store documents such as:
Job-role competency frameworks.
Job-specific scoring rubrics.
Skill definitions and skill synonyms.
Mandatory versus preferred skill guidelines.
Recruitment evaluation policy.
